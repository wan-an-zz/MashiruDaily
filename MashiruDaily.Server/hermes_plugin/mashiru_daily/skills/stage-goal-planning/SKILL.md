# 阶段目标制定（Stage Goal Planning）

## 何时使用

- 用户要求制定高考阶段计划 / 高考的阶段目标 / 高考分阶段提分方案/帮助用户高考提分
- 备战高考开始前、或用户想评估「当前水平 → 最终目标」的可行路径
- 与「daily-planning」「todo」两个 Skill 配套：本 Skill 产出阶段目标 → 每日计划 Skill 拆成每日任务 → todo 跟踪执行

## 定位与分工

本 Skill 用于为用户制定「阶段目标」：以半个月 / 一个月 / 任意时间周期为一个阶段，明确每个阶段要达到的目标。

**阶段目标 ≠ 每日任务。** 本 Skill 只产出「阶段层面的目标与方向」，不展开到每一天的具体任务。

| Skill                                    | 职责                    | 产出                                |
| ---------------------------------------- | --------------------- | --------------------------------- |
| 阶段目标制定（**stage-goal-planning**）（本 Skill） | 收集背景 → 评估差距 → 制定分阶段目标 | `situation.md`、`map.md`、`plan.md` |
| **每日计划制定**（daily-planning）               | 将阶段目标拆解为每日任务          | `plan-daily.md`                   |
| 每日代办布置（todo-assigning)                   | 将每日任务落实下去             | `todo.json`                       |

## 核心准则（必须遵守）

### 准则 1：阶段计划 ≠ 每日任务清单

阶段计划不是把每一天要做的事情全部列出来，而是以半个月或一个月或任意时间周期为一个阶段，为用户制定每个阶段的目标。

- 目标描述的是「阶段结束时应该达到的状态」
- 例：「第一阶段（8月）：数学函数与导数板块完成，年级排名提升至 110 名」
- 不要把「第一天做第 1 节，第二天做第 2 节」写进 `plan.md` —— 那是「daily-planning」Skill 的职责

### 准则 2：用年级排名制定计划

制定阶段计划时，要求使用年级排名制定计划。这要求你在了解用户的学校时就要清楚其学校的年级排名与省排名的映射关系。

- **为什么用排名不用分数**：分数受试卷难度、赋分规则影响，跨考试不可比；年级排名反映用户在群体中的相对位置，是更稳定的度量
- **最终目标用省排位表达**：目标院校录取线 → 最低省排位（如西湖大学 2026 年江西最低位次 725-772）
- **阶段目标用年级排名表达**：两者之间通过「学校年级排名 ↔ 省排名映射」转换（映射关系来自 Step 3 学校地位调查）

### 准则 3：边际递减效应

制定阶段计划时，不是把每个阶段需要提高的年级排名均分到每个阶段，而是要充分考虑**随着排名升高后提分的边际递减效应**。

- 排名越靠前，竞争对手越强，同样提升 10 名需要付出的努力越大
- 因此：前期（排名靠后时）可以设定较大的提升量，后期（排名靠前时）提升量应逐步缩小
- 越靠近最终目标，每个阶段的目标提升量越小

### 准则 4：从后往前、目标导向推理

制定计划时，要使用**从后往前、目标导向**的推理模式。

- 先确定最终目标（换算成年级排名），再倒推每个阶段的目标
- **示例**：用户的目标经过转化后是年级排名 30 名，而用户当前的年级排名是 200 名，当前距离高考还有三个月：

| 阶段 | 提升量 | 目标排名 |
|------|--------|---------|
| 第一阶段（第一个月） | +90 | 110 |
| 第二阶段（第二个月） | +60 | 50 |
| 第三阶段（第三个月） | +20 | 30 |

- 三个阶段提升量递减（90 → 60 → 20），体现边际递减；总量 = 200 − 30 = 170

## 工作流程

```
Step 1 明确高考事实（底层依据，所有规划基于此）
     ↓
Step 2 背景调查（基本信息）
     ↓
Step 3 学校地位调查（年级排名 ↔ 省排名映射）
     ↓
Step 4 目标院校与差距（依赖 Step 3 的映射）
     ↓
Step 5 资源盘点（知识点 ↔ 教辅映射 → map.md）
     ↓
Step 6 产出文档（situation.md → plan.md）
     ↓
Step 7 用户审查（plan.md 审查通过后才能记录）
```

### Step 1 明确高考相关事实

**目标**：建立规划依赖的底层事实，所有后续决策基于此。

1. **高考模式**
   - 新高考 3+1+2：语数外 + 首选（物理/历史）1 门 + 再选（化生政地）2 门
   - 旧高考文理分科
   - 特殊模式（如浙江**3+3模式**）
   - 注意：再选科目按**等级赋分**计分

2. **分数分布 6:2:2**（以满分 750 计）
   - 60% 基础题 → 约 450 分
   - 20% 中档题 → 累计约 600 分
   - 20% 难题 → 累计约 750 分
   - 含义：基础 + 中档占 80%、共 600 分，是绝大多数考生的分数池

3. **拿分规律**
   - 基础题和中档题可以靠**强化练习**拿到分
   - 难题需要**锻炼思维模式**才能拿分（无法只靠刷题量堆出来）

4. **知识点覆盖**
   - 拿满基础题和中档题的本质 = 把高中**所有知识点全部搞定**
   - 难题分靠的是个人思维能力

5. **时间分配原则**
   - 学生薄弱的学科应当占用更多时间，掌握较好的学科应当占用更少时间
   - 掌握好坏的判断标准 = **该科目分数对总分的贡献率**
   - 例：某科满分 100 只得 40（贡献率低）→ 薄弱，多分配时间；某科 100 得 90 → 强项，维持即可

### Step 2 背景调查（基本信息）

**目标**：建立用户基本档案，推断时间线。

需要收集并记录：

| 字段          | 说明                 | 用途                                       |
| ----------- | ------------------ | ---------------------------------------- |
| 省份          | 用户高考所在省份           | 决定高考模式（3+1+2 / 文理 / 特殊）与录取方式（裸分 / 综合评价等） |
| 年级          | 当前年级（高一 / 高二 / 高三） | 推断高考时间与剩余可利用时间                           |
| 所在学校        | 学校全称               | 学校地位调查的基础                                |
| 近三次考试平均年级排名 | 从当天开始往前数三次考试排名的平均值 | 当前水平基线                                   |

注意：
- 「从当天往前数三次考试」= 最近三次考试（含最近一次），取平均以消除单次考试波动
- 用户只记得最近一次排名时，先记录，后续补充
- 高考时间推断：高三 → 次年 6 月高考；剩余可利用时间 = 到高考的总天数

### Step 3 学校地位调查（省排位映射的关键）

**目标**：搞清楚「年级排名 ↔ 省排名」的映射关系，评估学校资源。

需要调查并记录的数据：

| 数据                     | 含义                  |
| ---------------------- | ------------------- |
| 是否省重点学校或市直中学           | 学校档次定位              |
| 去年特控（一本）上线率            | 定位特控线（一本线）大致年级排位    |
| 去年本科上线率                | 定位本科线大致年级排位         |
| 去年清华北大人数               | 定位清北线大致年级排位         |
| 去年 985、211 人数          | 定位985、211院校线的大致年级排位 |
| 去年高考年级第一名省排名           | 评估学校上限              |
| 用户所在年级总人数或用户所在选科方向的总人数 | 定位各档次院校区间的年级排位的数据基础 |

处理流程：

1. **问询**：询问用户的学校，并询问用户有关于以上数据的信息。若用户拒绝回答则不要追问。
2. **查证**：查询该学校的公开信息，与用户的说法**相互印证**，同时补充用户未回答的信息
   - 信息来源：学校官网、教育部门公告、媒体报道、第三方平台
3. **总结**：一句话总结该学校的情况
   - 例：「xx中学：xx省重点中学，理科约 1200 人，清北线约为年级排位xx名，985线约为年级排位xx名，211线约为年级排位xx名，特控线约为年级排位xx名，本科线约为年级排位xx名。」
4. **回答一个关键问题**
   - **问题**：学校年级排名如何映射省排名？
     - 给出各档次院校区间的年级排位的**1名**对应省排位的**n名**，例：xx中学的特控线和本科线区间内，年级排名每增长1名大约对应省排名增长1000名。
     - 实际计算中**不能**只结合单个指标，而是要综合清北线、985及211院校线、一本线、本科线对应的年级排名综合计算
5. **其他信息**：补充记录其他有用信息（如学校考试频率、分科制度等）

### Step 4 目标院校与差距

**目标**：确定最终目标（年级排位形式）并计算差距。

1. **记录目标院校**
2. **查询去年目标院校的录取分数线和最低省排位**
   - 查询方式：搜索引擎（如 jina reader：`r.jina.ai/https://www.bing.com/search?q=学校+年份+省份+录取分数线+位次`）
   - 注意区分招生方式：综合评价 vs 裸分（例：xx大学在xx省**只看裸分**，20xx年招生最低 669 分 / 位次 725-772，仅招约 10 人）
   - **位次比分数更可靠**：跨年分数波动大
1. **以院校的省排名映射其大致年级排位**
   - 映射依据：Step 3 学校地位调查得到的「年级排名 ↔ 省排名」关系
1. **计算差距**：目标年级排位 − 当前年级排位

### Step 5 资源盘点

**目标**：摸清用户可用的提分资源，建立「知识点 ↔ 资源」映射。

1. **明确用户目前打算使用哪些习题、教辅或网课提分**（记录）
   - 例：必刷一百讲（数学）、高中物理题型训练、某网课
2. **让用户将习题、教辅的目录上传，用识图模型或 OCR 识别**
   - 目录识别要点：完整层级必须保留（例如**章 → 模块 → 节 → 类型**）
   - 目录是「用户实际有什么」的第一手证据，比网上信息可靠
3. **读取各个学科的高考知识点汇总**
   - 内置知识点汇总（如果有）或用户提供
   - 知识点汇总以高考考纲 / 课标为纲，是全量知识地图
4. **将内置的高考知识点汇总和用户上传的习题、教辅目录对应起来**
   - 创建 **map.md**：教辅内容 ↔ 知识点的对应关系
   - 例：教辅「函数与导数·模块 5 恒成立问题」↔ 知识点「函数恒成立 / 存在性问题」
   - map.md是后续每日计划排任务的依据：知道某个知识点薄弱，就能从 map.md查到用哪个教辅的哪一节来补

### Step 6 产出文档

1. **situation.md**：记录上述所有需要记录的情况
   - 基本信息、高考事实、目标差距、学校地位、资源清单
2. **plan.md**：结合 situation.md，按核心准则产出分阶段目标计划
   - 用年级排名、边际递减、从后往前倒推
   - 注意留下至少一个月的计划冗余，严禁将计划直接延申到高考前一天才结束

### Step 7 用户审查

1. 将产出的 **plan.md** 呈现给用户审查（展示阶段目标分解表与依据说明）
2. **审查通过后**才能记录（保存 / 落地 plan.md，作为后续每日计划 Skill 的输入）
3. 审查未通过：根据用户反馈修改 plan.md，重新提交审查，直到通过为止
4. 用户明确安排的分布照单执行，不自行增删

### Step 8 进入第一阶段的每日计划

> 该步骤必须确保所有产出均已完成，包括：`plan.md`, `map.md`, `situation.md`。若缺少三者其一，则严禁进入Step 8。若用户未审查`plan.md`，同样严禁进入Step 8。

1. 再次检查上述三个产物是否齐全，若缺少其一则立刻掉头，返回前面的步骤重做。
2. 调用`daily-planning`Skill，跟随其进入后续步骤。

## 完整示例（虚构数据走一遍全流程）

**用户**：江西省高二学生，目标西湖大学（江西只看裸分，2026 年首年招生最低 669 分 / 省排位 725-772）
**当前**：近三次考试年级排名 210、198、205 → 平均约 204 名；学校为省重点，理科 1200 人

**Step 1 明确高考事实**：江西为新高考 3+1+2，再选科目等级赋分；基础+中档 600 分是分数池

**Step 2 背景调查**：省份=江西；年级=高二；学校=省重点高中；近三次平均年级排名 ≈ 204 名

**Step 3 学校地位调查**：该校去年第一名省排名约 400 名，年级前 200 大致对应省排位 8000-10000

**Step 4 目标院校与差距**：目标省排位 750 → 当前 8000+，差距巨大
对应年级排名目标：省排位 750 ≈ 年级 20-25 名

**Step 5 资源盘点**：数学用必刷一百讲、物理用高中物理题型训练；识别目录 → 建立 map.md

**Step 6 产出文档**：写出 situation.md 与 plan.md

**Step 7 用户审查**：提交 plan.md 给用户，通过后才记录

**Step 8 进入第一阶段的每日计划**：调用`daily-planning`Skill，进入第一阶段每日计划的规划

**从后往前倒推**（距离高考约 10 个月，设 4 个阶段）：

| 阶段 | 时间范围 | 目标年级排名 | 提升量 |
|------|---------|-------------|--------|
| 第一阶段 | 8-9 月 | 140 | +60 |
| 第二阶段 | 10-11 月 | 90 | +50 |
| 第三阶段 | 12-2 月 | 55 | +35 |
| 第四阶段 | 3-6 月 | 25 | +30 |

提升量递减（60 → 50 → 35 → 30）体现边际递减；实际数值需结合用户情况调整，此处仅展示推理模式。

## 陷阱与注意事项

1. **位次 > 分数**：跨年分数波动大，首年招生尤其不稳；对比一律用省排位
2. **赋分科目看赋分**：新高考赋分科目比较差距时用赋分，不用原始分
3. **学校映射是估算不是精确值**：年级排名 ↔ 省排位是映射关系，存在误差，要向用户说明
4. **时区问题**：服务器数据统一为北京时间（UTC+8）；若运行环境 `date` 不是 UTC+8，计算「剩余时间 / 阶段起止」前先换算
5. **不要越界排每日任务**：`plan.md` 只到阶段粒度；展开到日是「daily-planning」Skill 的职责
6. **计划要轻量**：阶段目标宁少勿多，聚焦 1-2 个最弱板块，其余留到后续阶段
7. **审查通过前不得记录**：plan.md 必须经用户审查通过后才能记录 / 落地，不可跳过 Step 7
8. **目录核对**：教辅目录以用户实际手头版本为准（网上/旧版目录可能与实体书结构不同），用户纠正时立刻改

## 与其他 Skill 的接口

- **输入**：用户自述（省份、学校、排名、目标、资源）+ 教辅目录（图片 / PDF）+ 知识点汇总
- **输出**：`situation.md`、`map.md`、`plan.md`（供「daily-planning」Skill 读取）
- **联动**：「daily-planning」Skill 读取 `plan.md` 的阶段目标 + `map.md` 的资源映射 → 按教辅内容量拆解每日任务；「todo」Skill 跟踪每日任务执行
