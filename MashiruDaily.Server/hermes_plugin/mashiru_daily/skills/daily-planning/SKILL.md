# 每日计划制定（Daily Planning）

## 何时使用

- 用户要求制定每日计划 / 每日任务 / 把阶段目标拆解到天
- 完成「阶段目标制定（stage-goal-planning）」Skill 之后，进入第 1 阶段
- 用户给出上一阶段考试情况、要进入新阶段时（第 n 阶段，n≠1）

## 定位与分工

本 Skill 用于把「阶段目标」拆解为「每日任务」：读取阶段目标计划已有的产出（`situation.md`、`plan.md`、`map.md`），把 `map.md` 中未完成的知识模块分配到每天，产出 `plan-daily.md`。

**每日任务 ≠ 阶段目标。** 本 Skill 只负责「到天」的拆解；「阶段层面的目标」由「阶段目标制定」Skill 负责，不要越界重做阶段规划。

| Skill                               | 职责                    | 产出                                |
| ----------------------------------- | --------------------- | --------------------------------- |
| 阶段目标制定（stage-goal-planning）         | 收集背景 → 评估差距 → 制定分阶段目标 | `situation.md`、`map.md`、`plan.md` |
| **每日计划制定**（daily-planning）（本 Skill） | 将阶段目标拆解为每日任务          | `plan-daily.md`                   |
| 每日代办布置（todo-assigning）              | 将每日任务落实下去             | `todo.json`                       |

## 文件约定

| 文件                | 内容                       | 更新者                               |
| ----------------- | ------------------------ | --------------------------------- |
| situation.md      | 用户情况（基本信息、考试情况、目标差距等）    | 阶段目标制定创建与维护；每日计划流程只读取，不更新         |
| plan.md           | 阶段目标计划（每阶段的目标年级排名、主攻方向）  | 阶段目标制定创建；每日计划只读取，仅在未达成/超出时按用户情况修改 |
| map.md            | 知识点 ↔ 教辅/资源映射，含各知识模块完成状态 | 阶段目标制定创建；每日计划在阶段结束后标记「已完成」        |
| **plan-daily.md** | **每日任务计划（本 Skill 的产出）**  | 每日计划制定                            |

## 工作流程

### 流程 A：计划第 1 阶段（完成 stage-goal-planning 之后）

```
完成 stage-goal-planning skill 后
    ↓
计划第 1 阶段
    ↓
读取 situation.md（已有）
    ↓
读取 plan.md（已有，第 1 阶段目标）
    ↓
根据用户的情况和本阶段的目标，从 map.md 中选取合适且适量的
知识模块（未完成模块）加入本阶段 plan-daily，任务分配到每天
    ↓
将 plan-daily 交给用户审查
```

1. **前置检查**：确认 stage-goal-planning 已完成，situation.md、plan.md、map.md 均已产出并通过用户审查
2. **读取**：situation.md（用户情况）、plan.md（第 1 阶段目标与主攻方向）、map.md（知识模块与资源映射）
3. **拆解**：根据用户的情况和本阶段的目标，从 map.md 中选取合适且适量的知识模块（未完成模块，聚焦本阶段主攻方向）加入本阶段 plan-daily.md，按教辅内容量把任务分配到每天
4. **审查**：将 plan-daily.md 交给用户审查，通过后才可开始执行

### 流程 B：计划第 n 阶段（n≠1，用户给出上一阶段考试情况后）

```
用户给出了上一阶段的考试情况
    ↓
计划第 n 阶段
    ↓
读取 situation.md（已有，背景档案）
    ↓
读取 plan.md（已有，阶段目标）
    ↓
判断上一阶段目标达成情况
├── 已达成 → 继续（plan.md 无需修改）
├── 未达成 → 根据用户的情况修改 plan.md，使其吻合用户的节奏 → 用户审查（plan.md）
└── 超出   → 根据用户的情况修改 plan.md，使其吻合用户的节奏 → 用户审查（plan.md）
    ↓
读取上一阶段的 plan-daily.md，明确已完成的知识模块，
在 map.md 中将已完成的知识模块备注为「已完成」
    ↓
询问用户本次考试中出现的漏洞（漏洞无论已完成/未完成模块都要补）
    ↓
根据用户的情况和本阶段的目标，从 map.md 中选取合适且适量的知识模块
（未完成模块 + 考试漏洞模块）加入本阶段 plan-daily.md，将任务分配到每天
    ↓
将 plan-daily 交给用户审查
```

1. **输入**：用户给出上一阶段考试情况（成绩、排名等）
2. **计划第 n 阶段**：进入新阶段规划
3. **读取 situation.md**：作为背景档案读取，**不更新**（situation.md 由阶段目标制定 Skill 维护）
4. **读取 plan.md**：读取已有阶段目标作为拆解依据，**不主动更新**
5. **判断上一阶段目标达成情况**：
   - **已达成**：plan.md 无需修改，直接继续
   - **未达成 / 超出**：**根据用户的情况修改 plan.md**，使其吻合用户的节奏（未达成 → 调整目标或方法；超出 → 说明原计划偏保守，可加速或调高目标），修改后必须交给用户审查，通过后继续
   - **注意**：判断是否达成目标**不是**数值上的绝对的大小比较，而是带有**冗余**的比较。例如：上一阶段目标为120名，而考试成绩为125名，虽然数值上未达成目标，但是二者**差值很小，可以忽略**，故**视为**达成目标。
1. **回填 map.md**：读取上一阶段的 plan-daily.md，明确已完成的知识模块，在 map.md 中将已完成的知识模块备注为「已完成」
2. **询问漏洞**：询问用户本次考试中出现的漏洞有哪些（这些漏洞无论属于已完成还是未完成的知识模块，都需要补）
3. **拆解**：根据用户的情况和本阶段的目标，从 map.md 中选取合适且适量的知识模块加入本阶段 plan-daily.md：
   - 考试漏洞模块：**必须加入**，无论 map.md 中标记「已完成」还是「未完成」（已完成但考试暴露漏洞 = 未真正掌握，需复习巩固）
   - 常规模块：map.md 中未完成的知识模块（按 plan.md 本阶段主攻方向与用户情况筛选，合适且适量）
   - 将任务分配到每天
   - 完成plan-daily.md后，必须根据本次plan-daily.md中已规划的任务量和剩余的任务量估计所有知识模块全部完成的天数，并比较预计完成的天数和当前距离高考的天数。若**预计完成的天数**大于**当前距离高考的天数-15d**，则**必须重新规划**；小于则反之。
1. **审查**：将 plan-daily.md 交给用户审查，通过后才可开始执行

## 拆解规则（map.md → plan-daily.md）

1. **选模块依据**：根据**用户的情况**（当前水平、薄弱点、考试反馈）和**本阶段的目标**（plan.md 本阶段主攻方向），从 map.md 中选取**合适且适量**的知识模块——不贪多，聚焦最需要的
2. **漏洞模块必须补**：询问用户本次考试出现的漏洞，漏洞对应的知识模块**无论属于已完成还是未完成**都必须加入 plan-daily（已完成但考试暴露漏洞 = 未真正掌握，需复习巩固）
3. **常规模块**：map.md 中「未完成」的知识模块；已在 map.md 标记「已完成」且考试未暴露漏洞的模块不再重复安排
4. **按量分配**：根据教辅/资源的内容量（节数、页数、网课时长）估算每天可完成量，把模块拆到每天
5. **记录**：每天的任务记录学科、任务内容、对应知识模块、教辅/资源、章节/页码、预计耗时；执行后更新完成状态

## 完整示例（虚构数据走一遍流程 B）

**前置**：第 1 阶段已结束，用户反馈考试：年级排名从 204 → 170（第 1 阶段目标 140，**未达成**）

1. 用户给出考试情况（排名 170）→ 计划第 2 阶段
2. 读取 situation.md（背景档案）
3. 读取 plan.md（原计划第 2 阶段目标排名 90，第 3 阶段目标70名）
4. 判断：未达成 → 根据用户的情况修改 plan.md，使目标吻合用户节奏（如把第 2 阶段目标放缓为 110，第 3 阶段目标放缓为85名，第 n 阶段以此类推）→ 交给用户审查 → 通过
5. 读取第 1 阶段 plan-daily.md，确认已完成的知识模块（如「函数恒成立」），在 map.md 中标记「已完成」
6. 询问漏洞：用户说本次考试三角函数大题失分严重 → 该漏洞模块加入第 2 阶段 plan-daily.md（即使 map.md 中已标记「已完成」也要补）
7. 根据用户情况和第 2 阶段目标，从 map.md 选取合适且适量的未完成模块（如「三角函数」剩余小节）加入 plan-daily.md，按教辅节数分配到每天
8. 将 plan-daily.md 交给用户审查 → 通过 → 执行

## 陷阱与注意事项

1. **漏洞模块例外**：map.md 中标记「已完成」的模块默认不再排入 plan-daily，**但考试暴露漏洞的已完成模块必须重新安排**（复习巩固）
2. **未达成/超出都要改 plan.md**：不能无视上一阶段的偏差继续按原计划走；修改要吻合用户的实际节奏，且修改后必须过用户审查
3. **已达成也不能跳过回填**：即使已达成，也要读取上一阶段 plan-daily.md 回填 map.md 的完成状态
4. **任务量要轻量**：每天任务宁少勿多，排不下的留到下阶段
5. **审查通过前不得执行/记录**：plan-daily.md 必须经用户审查通过后才能作为执行依据
6. **时区问题**：服务器数据统一为北京时间（UTC+8）；若运行环境 `date` 不是 UTC+8，算「日期 / 天数 / 阶段起止」前先换算
7. **不要越界重做阶段规划**：阶段目标、目标排名、主攻方向都在 plan.md 里定好了，本 Skill 只做「拆到天」

## 与其他 Skill 的接口

- **输入**：situation.md、plan.md、map.md（stage-goal-planning 产出）+ 用户上一阶段考试反馈
- **输出**：plan-daily.md（用户按此执行，阶段结束后反馈考试情况 → 回到流程 B）
- **联动**：「阶段目标制定」产出阶段目标 → 本 Skill 拆成每日任务 → 「todo-assigning」跟踪执行
