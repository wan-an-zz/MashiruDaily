# MashiruDaily 客户端与服务器通信协议

> 本文档以当前代码实现为准，定义 MashiruDaily 客户端与 FastAPI 服务器之间的通信契约。
> 当前客户端同步链路以“客户端 ⇄ FastAPI 服务器（:8123）”为主；推送成功后客户端还会在后台把更新快照发送给 Hermes Webhook 网关（:8644），触发 Agent 生成消息，并通过 `GET /api/messages` 拉取反应。

## 1. 系统拓扑

```
┌─────────────────────┐   GET /api/todo/meta      ┌──────────────────────┐
│  MashiruDaily 客户端 │ ────────────────────────▶ │  FastAPI 服务器       │
│  (桌面 / Android /   │   GET /api/todo           │  :8123               │
│   TUI)               │   GET /api/messages       │  todo.json           │
│                     │ ◀──────────────────────── │  todo-meta.json      │
│                     │   POST /api/update         │  messages-to-user.json│
│                     │ ────────────────────────▶ │                      │
└─────────────────────┘                            └──────────┬───────────┘
                                                              │ todo_* 工具
                                                              ▼
                                                       Hermes Agent（cron 每日运行）
```

- 客户端通过 `ServerBaseUrl` 访问服务器。
- 服务器直接读写 `todo.json`、`todo-meta.json`。
- Hermes Agent 通过 `hermes_plugin` 的 `todo_*` 工具维护 `todo.json`，通过 `speak_to_user` 写消息文件。
- Hermes Webhook 网关（:8644）用于在客户端推送成功后触发 Hermes Agent 生成“反应”消息；客户端通过 `GET /api/messages` 拉取该消息。

## 2. 数据文件与字段

### todo.json（服务器侧唯一待办数据源）

位于 `MASHIRU_DATA_DIR/todo.json`，顶层是数组，字段为蛇形命名：

```json
[
  {
    "id": "22222222-2222-2222-2222-222222222222",
    "title": "买菜",
    "is_completed": true,
    "created_at": "2026-08-10T09:00:00+08:00",
    "completed_at": "2026-08-10T11:30:00+08:00"
  }
]
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 条目唯一标识 |
| `title` | string | 标题 |
| `is_completed` | bool | 是否已完成 |
| `created_at` | string (ISO 8601 UTC+8) | 创建时间 |
| `completed_at` | string 或 null | 完成时间；未完成为 null |

`has_synced` 是客户端本地字段，`todo.json` 和所有网络事件中都不得出现。

### todo-meta.json

位于 `MASHIRU_DATA_DIR/todo-meta.json`：

```json
{
  "date": "2026-08-10",
  "updated_at": "2026-08-10T17:00:00+08:00",
  "count": 12
}
```

### messages-to-user.json

位于 **`MASHIRU_DATA_DIR` 的父目录**：

```
$HOME/.mashiru-daily/messages-to-user.json
```

```json
{ "text": "今天记得完成数学作业", "time": "2026-08-22T21:00:00+08:00" }
```

## 3. 事件类型

客户端推送的 `events[].event_type` 固定为以下 5 种：

| 类型 | 触发场景 | 语义 |
|---|---|---|
| `todo_added` | 新建待办 | upsert，服务器不存在该 id 则创建 |
| `todo_updated` | 修改标题；补推历史待同步项 | upsert，存在则更新，不存在则创建 |
| `todo_completed` | 标记完成 | 完整条目快照 |
| `todo_reopened` | 重新打开 | 完整条目快照 |
| `todo_deleted` | 删除待办 | 服务器按 `id` 删除 |

payload 一律是完整条目快照，字段为：

```json
{
  "id": "...",
  "title": "...",
  "is_completed": false,
  "created_at": "...",
  "completed_at": null
}
```

## 4. 拉取接口

### 4.1 `GET {ServerBaseUrl}/api/todo/meta`

返回：

```json
{
  "date": "2026-08-10",
  "updated_at": "2026-08-10T17:00:00+08:00",
  "count": 12
}
```

- `count` 始终取 `todo.json` 实时长度。
- `todo-meta.json` 缺失时服务器自动创建。
- 返回非 200 或响应缺少合法 `updated_at` 时，客户端判定拉取流程失败。

### 4.2 `GET {ServerBaseUrl}/api/todo`

返回蛇形命名待办数组；文件缺失返回空数组。

### 4.3 `GET {ServerBaseUrl}/api/messages`

返回：

```json
{ "exist": true, "text": "今天记得完成数学作业", "time": "2026-08-22T21:00:00+08:00" }
```

- 文件不存在：`200 {"exist": false, "text": "", "time": ""}`
- 文件存在但结构不合法（缺 `text` / `time` 键、JSON 非法或顶层不是对象）：`500 {"detail": "messages-to-user.json 文件不合法"}`
- JSON 非法或顶层不是对象：`500 {"detail": "messages-to-user.json 文件不合法"}`
- 客户端在推送成功并触发 Hermes Webhook 后，会在固定时间窗口内轮询此接口获取 Agent 反应。

## 5. 推送接口

### 5.1 `POST {ServerBaseUrl}/api/update`

请求体：

```json
{
  "event_type": "update",
  "updated_at": "2026-08-22T21:00:00+08:00",
  "events": [
    {
      "event_type": "todo_updated",
      "timestamp": "2026-08-22T21:00:00+08:00",
      "payload": {
        "id": "22222222-2222-2222-2222-222222222222",
        "title": "买菜",
        "is_completed": false,
        "created_at": "2026-08-10T09:00:00+08:00",
        "completed_at": null
      }
    }
  ]
}
```

- 顶层 `event_type` 固定为 `"update"`。
- 顶层 `updated_at` 为客户端本次变更的 UTC+8 时间。
- `events` 为事件数组，单批最多 15 条（客户端按批发送）。

### 5.2 请求头

客户端仍发送以下 HMAC 签名头：

| Header | 值 | 说明 |
|---|---|---|
| `X-Webhook-Timestamp` | Unix 秒字符串 | 签名输入 |
| `X-Webhook-Signature-V2` | 小写 hex HMAC-SHA256 | 对 `"{timestamp}.{rawBody}"` 计算 |
| `X-Request-ID` | UUID | 请求/事件批唯一标识 |

**当前 FastAPI 服务端不校验这些头**，仅客户端保留签名计算逻辑。

### 5.3 响应

全部成功（HTTP 200）：

```json
{ "success": true, "error_ids": [], "success_ids": ["id1", "id2"] }
```

存在失败条目（HTTP 500）：

```json
{ "success": false, "error_ids": ["failed-id"], "success_ids": ["ok-id"] }
```

客户端对 500 的处理：

- 解析 `error_ids` / `success_ids`；
- 仅把 `success_ids` 中的条目标记为已同步；
- 只把成功条目重组后用于 Hermes 反应链路；
- 500 视为终态，不再重试。

### 5.4 客户端推送成功后的 Hermes 反应链路

1. `POST {ServerBaseUrl}/api/update` 成功后，客户端把本次更新快照投递到内部 `Channel`。
2. 后台 Worker 串行向 `{HermesBaseUrl}/webhooks/{WebhookRouteName}` POST 同一事件体；500 部分成功时只发送 `success_ids` 对应条目。
3. Hermes Agent 收到后通过 `speak_to_user` 写入 `messages-to-user.json`。
4. Worker 在固定窗口（每次约 30 秒，最多 4 次）内轮询 `GET {ServerBaseUrl}/api/messages`，拉取 Agent 消息。
5. 该流程在客户端后台异步执行，不阻塞同步主流程，也不持有同步 `_gate`。

## 6. 客户端同步流程

1. 加载设置；`SyncEnabled=false` 时不联网。
2. `GET /api/todo/meta` 获取 `updated_at`。
3. 比较服务器 `updated_at` 与本地 `LastSyncedAt`：
   - `LastSyncedAt` 为空或无法解析：需要拉取；
   - 服务器 `updated_at` 严格晚于 `LastSyncedAt`：需要拉取；
   - 否则：不需要拉取。
4. 需要拉取：`GET /api/todo` 整体替换本地 todo，全部标记 `HasSynced=true`，持久化 `LastSyncedAt=服务器 updated_at`。
5. 不需要拉取：把本地 `HasSynced=false` 的条目统一按 `todo_updated` 批量推送。
6. 推送成功（含部分成功）后：客户端用本次请求体的 `updated_at` 推进本地 `LastSyncedAt`，再把 Webhook 任务投递到后台 `Channel`，由独立 Worker 执行 Hermes POST 和 `/api/messages` 轮询。

### 推送重试

- 总尝试次数：`MaxRetryAttempts + 1`。
- `429`：退避约 2 秒后重试。
- 其他非 2xx：重试。
- 网络异常/超时：重试。
- 500：解析部分成功，终态返回。
- 重试耗尽：同步状态置 `Error`，条目保持未同步，下次继续推送。

## 7. 客户端设置

| 字段 | 默认值 | 当前用途 |
|---|---|---|
| `ServerBaseUrl` | 空字符串 | 拉取与推送基础地址，如 `http://<主机>:8123` |
| `HermesBaseUrl` | `http://localhost:8644` | Hermes Webhook 基地址，用于推送更新快照给 Hermes Agent；设置页连接测试也用它 |
| `WebhookRouteName` | `todo-sync` | Hermes Webhook 路由名，当前同步代码用于触发 Agent 反应 |
| `WebhookSecret` | 空 | 用于计算推送签名（当前服务端未校验） |
| `SyncEnabled` | `false` | 同步总开关 |
| `MaxRetryAttempts` | `3` | 推送失败最大重试次数 |
| `TimeoutSeconds` | `10` | HTTP 超时秒数 |
| `LastSyncedAt` | 空 | 上次成功拉取或推送后服务器 `updated_at` |

`ServerBaseUrl` 没有默认同 `HermesBaseUrl` 的回退逻辑；启用同步时必须显式填写。

## 8. updated_at 语义

- `todo-meta.json` 的 `updated_at` 表示 `todo.json` 的上一次更新时间。
- Hermes 侧在 `todo_meta_stamp` 运行时刷新：`setup_server.py` 首次引导、每日 Hermes cron 结束。
- 客户端通过 `/api/update` 推送导致 `todo.json` 修改时，服务端使用请求体顶层的 `updated_at` 刷新该字段。
- 客户端成功推送后同步推进本地 `LastSyncedAt`，因此“判断是否拉取”的比较逻辑保持不变，不会把自己的推送误判为需要全量拉取。

## 9. Hermes Webhook 网关说明

Hermes Webhook 网关（:8644）和 `configure_webhook.py` 仍保留在仓库中，当前用途是“触发 Hermes Agent 对客户端更新做出反应”：

- `POST {ServerBaseUrl}/api/update` 仍然负责直接改写 `todo.json`，是数据权威链路；
- 客户端推送成功后，再把同一事件快照 POST 到 `{HermesBaseUrl}/webhooks/{WebhookRouteName}`，触发 Hermes 生成消息；
- Hermes 通过 `speak_to_user` 写入 `messages-to-user.json`，客户端再通过 `GET {ServerBaseUrl}/api/messages` 拉取反应。
